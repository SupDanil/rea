## 📝 ФОРМЫ: ТОЛЬКО TanStack Form + zod

> 🔴 **Значения формы не хранятся в `useState`.** Форма — `useForm` (TanStack Form), правила — zod-схема из
> `src/forms/schemas.ts`. Полные правила и пример: [`docs/FORMS.md`](../../docs/FORMS.md).

* Поле — `<form.Field>` поверх `TextField` / `Checkbox` дизайн-системы.
* Кнопка отправки блокируется через `form.Subscribe` + `schema.safeParse(...)`, без отдельного `useState`.
* `useState` — только для состояния экрана и хода сценария (шаг входа, открытая шторка, ответ сервера).
* Каждая форма покрыта тестами: схемы — `src/forms/schemas.test.ts`, поведение — в тестах страниц.

## 🔗 Подключение к локальному бэкенду и админке (`REA-ADMIN`)

Админка и бэкенд работают на **`http://localhost:3000`** (проект `REA-ADMIN`).

Чтобы клиент отправлял заказы в реальную базу данных админки и они сразу отображались на экране бариста (KDS):

### 1. Создайте файл `.env.local` в папке `app/`:
```env
VITE_API_URL=http://localhost:3000/api/v1
```

### 2. Запустите клиент:
```bash
npm run dev
```
Клиент откроется на **`http://localhost:5173`**.

## 🧪 Сквозное тестирование связки Клиент + Админка

1. **Терминал 1 (Админка + API):**
   ```bash
   cd REA-ADMIN && npm run dev
   ```
   (Админка и бэкенд на `http://localhost:3000`)
2. **Терминал 2 (Клиент):**
   ```bash
   cd REA/app && npm run dev
   ```
   (Клиент на `http://localhost:5173`)
3. **Проверка в браузере:**
   * Откройте табло бариста: `http://localhost:3000/kds`
   * В соседней вкладке откройте клиент: `http://localhost:5173`
   * Оформите заказ — он моментально появится со звуковым сигналом у бариста на табло KDS и в журнале заказов `/orders`.
   * Бариста нажимает «Готовим» $\rightarrow$ «Готово» $\rightarrow$ «Выдан»: на клиенте статус меняется в реальном времени через SSE без перезагрузки страницы!
