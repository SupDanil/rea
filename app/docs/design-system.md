# Единая система оформления клиента

Рефакторинг текущего приложения: API, структура данных каталога и сценарии заказа сохранены. Стиль задаётся CSS custom properties; Tailwind использует те же значения, а не отдельную палитру.

## Что и где менять

| Файл | Ответственность |
| --- | --- |
| `src/styles/tokens.css` | Все палитры, шрифты, шкалы текста, расстояния, радиусы, линии, размеры контролов и контейнеров, эффекты, брейкпоинты |
| `src/styles/components.css` | Компоновка и состояния общих компонентов на этих токенах |
| `src/components/` | Типизированные React-компоненты с событиями, ref, доступностью и поведением |
| `src/components/ui.ts` | Оставшиеся общие рецепты типографики и компоновки; кнопок и полей здесь больше нет |
| `src/index.css` | Подключение системы, базовые стили, прежние keyframes и переходы модальных окон |
| `index.html` | Загрузка файлов шрифтов и установка темы до первого отображения |

Три уровня: **базовые шкалы → семантические роли → компоненты**. Например: `--space-unit` → `--control-md` → `.ui-control--md`; `--accent` → `--button-bg` → `.ui-button--primary`.

## Как поменять бренд

Менять существующие объявления в `tokens.css`, а не добавлять перекрывающий файл поверх страниц:

```css
:root {
  --accent: #5943a6;
  --accent-2: #49358e;
  --accent-ink: #ffffff;
  --bg: #f6f4ef;
  --surface: #fffdfa;
  --ink: #242126;

  --font-body: 'Onest', system-ui, sans-serif;
  --font-heading: 'Onest', system-ui, sans-serif;
  --space-unit: .25rem;
  --type-scale: 1;
  --radius-scale: .75;
  --stroke-width: 1px;
  --button-radius: var(--radius-control);
}

:root[data-theme='dark'] {
  --accent: #b9a7f2;
  --accent-2: #c9bbf7;
  --accent-ink: #20172f;
  --bg: #17151a;
  --surface: #211e25;
  --ink: #f5f1fa;
}
```

Это пример, он не включён в текущую палитру. Для нового шрифта также загрузить его файл в `index.html`; одно CSS-имя не скачивает шрифт.

- **Плотность:** `--space-unit` влияет на все `p-*`, `m-*`, `gap-*`, `w-*`, `h-*`, `size-*` и числовые сетки. `--page-gutter`, `--panel-padding`, `--section-gap` позволяют менять отдельные роли.
- **Текст:** `--type-scale` масштабирует всю шкалу. Роли `--type-caption`, `--type-body`, `--type-control`, `--type-title`, `--type-heading` можно настраивать отдельно. Также есть веса, интерлиньяж и трекинг.
- **Скругления:** `--radius-scale` масштабирует обычные углы. `--radius-pill` независим: круглые значки и капсулы остаются круглыми. Для формы кнопок есть `--button-radius`, для поля — `--field-radius`, счётчика — `--stepper-radius`.
- **Линии:** `--stroke-width` задаёт основную толщину; усиленные границы, фокус и кольца производные. `--icon-stroke` отдельно управляет SVG-иконками.
- **Цвета и эффекты:** `--surface*`, `--ink*`, `--line*`, `--accent*`, `--open`, `--pending`, `--danger`; `--shadow-*`, стекло, размытие и прозрачность также находятся здесь. Производные тени/границы используют `color-mix`, поэтому следуют смене палитры.
- **Карточка напитка:** `--pd-*` — отдельные роли для её поверхности и контраста. Текст и выбранный акцент связаны с общей темой; фон студии можно настроить отдельно.
- **Адаптив:** `--layout-*` управляют шириной и высотой контейнеров. Брейкпоинты заданы в `@theme`; после их изменения нужен пересчёт CSS сборщиком. Это не runtime-переменные media query.
- **Браузер и PWA:** `theme-color` читается из `--bg`; установочный manifest получает светлый `--bg` при сборке. Для этой роли требуется HEX-цвет.

Токены редактируются на `:root` / `:root[data-theme='dark']`. Если нужен локальный вариант, он явно задаётся в компоненте: производные custom properties вычисляются в области объявления. Поэтому градиенты `.brand-product`, `.brand-promo`, `.brand-article`, `.brand-level` объявлены в `tokens.css` на соответствующих элементах, где доступны API-цвет `--tint` и номер уровня.

## Матовый Soft UI

Эталон материала — `SegmentedControl`: ровная матовая поверхность, мягкий подъём общей панели и углубление выбранного сегмента.

Выбранное состояние использует общую `--selection-surface` и вдавленный материал у сегментов, вкладок добавок и фильтров. У `SegmentedControl` тень корпуса центрирована (`--segment-shell-shadow`), а нижний внутренний блик ослаблен (`--segment-selected-shadow`): направленная вниз тень визуально утолщала нижнюю кромку при равных отступах 6 px. На мобильном экране высотой до 700 px сцена напитка уменьшается через `--product-stage-min`; размер стакана учитывает видимую область арта, а кнопки сохраняют 44 px. Стрелки десктопной карусели находятся по краям строки пагинации, ниже кнопок выбора.

В промо показывается одна краткая подводка из админки. Статья без обложки использует арт первого связанного товара, сохраняя переход в статью. Если арта нет, текст занимает всю ширину. Открытие промо и быстрое добавление — отдельные нативные кнопки.

- `--ceramic-raised` — обычные кнопки и панели управления; `--ceramic-selected` — выбранные варианты и нажатие. Одинаковая модель света в обеих темах.
- Основная покупка использует `Button variant="primary"`: фирменный акцент, общий радиус и мягкая тень, без отдельного глянцевого градиента для больших кнопок.
- Постоянные карточки используют более спокойный `--product-card-shadow`; всплывающие окна остаются выше через `--lift-shadow`.
- Информационные метки и счётчики плоские. Вкладки и добавки не получают цвет основного действия только из-за выбора.
- Основные области касания — не меньше 44 px; служебные подписи в контролах — от 12 px. Название товара занимает до двух строк.
- Фотографии, иллюстрации и фоновые свечения из админки остаются самостоятельным слоем, их не перекрашивают правила кнопок.
- Материал задаётся явным компонентом/классом в `components.css`. Не добавлять переопределения вида `button.bg-accent` или `span.bg-pd-glass` после Tailwind utilities: цветовой класс не определяет роль элемента.

## Общие компоненты

| Компонент | Контракт / применение |
| --- | --- |
| `Button` | `variant`: primary, secondary, danger, ghost, plain; `size`: sm, md, lg; `fullWidth`. По умолчанию `type="button"`; отправка формы только через `type="submit"` |
| `IconButton` | Тот же контракт, квадратный размер и обязательный `aria-label`; шапки, закрытие, служебные действия |
| `QuickAddButton` | `added`, `onClick`, `aria-label`; одна кнопка с плюсом/подтверждением в каталоге, баннере и статье |
| `TextField` | `fieldSize`: md, xl, code, inline; `error`, нативные атрибуты, события, ref. Используется при входе, в корзине и настройках |
| `Checkbox` | Нативный checkbox с общей геометрией и акцентом; доступное имя через label |
| `QuantityStepper` | `value`, обработчики, подписи кнопок, ограничения и disabled. Корзина и добавки; решение об удалении и лимите остаётся у вызывающего кода |
| `SegmentedControl` | `value`, `options`, `onChange`, `label`, `tone`, `stretch`, `cycleOnSelected`. Размер, температура и время выдачи; общая подпись `detail` для объёма. Стрелки, Home/End, обход недоступных вариантов, одна точка входа с Tab; повторный тап циклически меняет выбор только при `cycleOnSelected` |
| `ChoiceButton`, `ChoiceFace` | Общий матовый выбор: `selected`, `tone`. `ChoiceButton` передаёт выбранное состояние через `aria-pressed`; `ChoiceFace` рисует ту же поверхность внутри уже интерактивной карточки, без вложенных кнопок |
| `SwitchRow` | `checked`, `onChange`, `label`, необязательные description/leading; настройки и подарочный напиток |
| `Surface` | `tone`, `padding`, `as`: div/section/ul/li/dl. Общая оболочка панели; сохраняет семантику списков |
| `Sheet`, `SheetBody`, `SheetDock`, `Summary` | Существующие общие компоненты переведены на токены и общую оболочку |

```tsx
<Button variant="primary" size="lg" fullWidth onClick={save}>
  Сохранить
</Button>
<TextField aria-label="Имя" value={name} onChange={changeName} error={invalid} />
<Surface as="dl" padding="md"><SummaryRow label="Итого" amount={total} /></Surface>
```

`className` используется для размещения (`flex`, `gap-*`, `w-full`, адаптивные колонки). Повторяющееся новое оформление добавлять вариантом компонента. `plain` — для собственных составных контролов, вкладок и кликабельных карточек; это не вариант для копирования оформления primary-кнопки на страницу.

## Что не является бренд-токеном

- Фотографии, логотипы, цвета ингредиентов и иллюстраций из API: смена CSS не перерисовывает изображения.
- Геометрия SVG в `ItemArt.tsx`; чёрный/белый QR в `QrCodeView.tsx` сохраняют назначение и читаемость.
- Проценты, доли сетки, `100%`, viewport/safe-area, координаты после измерения DOM: это правила компоновки.
- Физика и хореография существующих анимаций в `utils/motion.ts`, `utils/morph.ts`, keyframes и таймеры сценариев. Рефакторинг не меняет их траектории и жизненный цикл.
- Тестовые fixtures не являются источником runtime-данных.

## Проверки

```sh
# Node 22+, из app/
npm run lint        # включает check:design; также выполняется существующим CI
npm test
npm run build

# Запустить API и клиент отдельно, затем:
npm run test:design -- http://localhost:5173/
# Необязательно:
DESIGN_SCREENSHOTS=/tmp/rea-design-qa npm run test:design
# Если Chrome не найден автоматически:
CHROME_PATH=/path/to/chrome npm run test:design
```

`controls.test.tsx` проверяет нативную семантику, ref, submit, disabled, validation, ограничения счётчиков, клавиатурный выбор, switches и семантику Surface. Старые тесты страниц продолжают проверять заказ, карточку товара и анимации; проверка положения бейджа нутриентов обновлена на токен расстояния.

`check-design-system.mjs` запрещает raw HEX/RGB/HSL, стандартные Tailwind-палитры вместо семантических цветов, произвольные фиксированные размеры, встроенные эффекты и нативные button/input вне базовых компонентов. Он сканирует runtime TypeScript и CSS вне файла токенов, а не контент SVG и тестовые данные; это защита от типовых регрессий, не полный CSS-анализатор.

`design-system-check.mjs` использует отдельный временный Chrome-профиль. Проверяет распространение изменений токенов на реальные элементы каталога, обе темы и размеры 320×568, 390×844, 416×657, 616×816, 768×1024, 1440×900. Это CSS viewport, а не заявление о проверке физического складного устройства. Скриншоты сохраняются при указании переменной окружения. Нужен доступный реальный каталог; серверные ошибки не заменяются моками.

Без авторизации корзина и профиль штатно показывают вход — тест явно отмечает это и не выдаёт его за проверку авторизованных экранов. Он не отправляет SMS, заказы или платежи; добавление товара меняет только корзину временного браузерного профиля. Проверки авторизованных сценариев выполняются существующими компонентными тестами.

## Результат проверки 2026-11-05

- Vitest: **309 тестов, 41 файл — passed**; TypeScript и production-сборка прошли.
- Защита `check:design` прошла. ESLint: без ошибок, остаются прежние предупреждения `no-explicit-any`.
- В Chrome проверено распространение токенов на реальное меню: радиус 24→12 px, отступ 10→12.5 px, текст 10→12 px, толщина границы 1→3 px, кнопка 36→45 px; шрифт и связанный акцент также меняются. Меню и карточка напитка визуально просмотрены при 390×844.
- Полная матрица браузерных экранов **не завершена**: во время проверки `GET /api/v1/catalog` начал отвечать HTTP 500. Данные не подменялись. После восстановления API повторить `npm run test:design`; отсутствие авторизации отдельно ограничивает проверку корзины и профиля формой входа.
- `SegmentedControl` не скользит: выбор вдавливается на месте, меняется только `opacity` вдавленного слоя. Пружинных easing и анимации ширины у него нет.
