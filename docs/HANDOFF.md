## Следующая большая задача: архитектура (визуально ничего не менять)

Пользователь хочет подготовить код к бэкенду с админкой (из неё будут приходить продукты и т. п.).
- **TanStack Query** — сервер-стейт и есть состояние приложения (кеш запросов): меню (категории, позиции, группы добавок), заказы (создать/отменить/оценить), профиль/вход по SMS, лояльность, проверка промокода.
- **Контекст** — только то, чего нет на бэке: корзина (localStorage), тема, тосты, UI-состояние анимаций.
- Предлагаемые слои: `api/` (DTO-типы под будущий бэк, интерфейс клиента, http-реализация по `VITE_API_URL`, мок-бэкенд на текущих данных из `data/menu.ts` и localStorage с теми же ключами `zerno-*`), `domain/` (чистая логика: каталог/индексы, корзина, расчёт цены, статусы заказа, лояльность, выбор добавок), `queries/` (ключи и хуки, меню через `useSuspenseQuery`), `state/` (клиентский контекст, разбить на корзину/тему/UI).
- Сейчас синхронный доступ к меню (`itemById`, `groupById`, `topCategories`… из `data/menu.ts`) в ~20 файлах — перевести на хук каталога.
- **Тесты**: Vitest + Testing Library + jsdom (заглушки `matchMedia`, `ResizeObserver`, `scrollTo`, `Element.animate`); покрыть domain, мок-API, хуки, ключевые сценарии (добавить в корзину, удалить, оформить). Добавить `npm test` в CI перед сборкой.
