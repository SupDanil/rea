# Промт: полный редизайн клиентского PWA «shit кофе» (REA/app) — стиль 2026

Ты — ведущий продуктовый дизайнер и senior frontend-инженер. Задача: полностью переделать визуальный стиль и поведение интерфейса клиентского PWA кофейни «shit кофе» в `REA/app`, опираясь на самые сильные тренды веб-дизайна 2026 года. Это не косметика и не перекраска: модалки, шторки, кнопки, переключатели, тосты, навигация могут **выглядеть и работать совершенно иначе**, если так лучше и красивее. ## 2. Художественное направление: «Espresso Glass»

Одна цельная идея: **жидкое стекло поверх живого кофейного света**. Интерфейс как витрина кофейни вечером: тёплый свет, пар, блики на стекле, крупный уверенный шрифт.

Используем тренды 2026:

1. **Liquid Glass (главный язык).** Стекло как в iOS 26: поверхности преломляют то, что под ними, у них светлая кромка сверху, тонкий внутренний блик и реакция на нажатие (лёгкое сжатие и вспышка блика). Стекло только на плавающих слоях: док, шторки, тосты, панели управления. Контент (карточки, списки) остаётся плотным и читаемым.
   - Рецепт: `backdrop-filter: blur(20–28px) saturate(160–190%)`, фон `rgb(255 255 255 / .12–.6)` в зависимости от темы, `border: 1px solid rgb(255 255 255 / .3–.45)`, `box-shadow: inset 0 1px 0 rgb(255 255 255 / .5), inset 0 -1px 0 rgb(255 255 255 / .1), 0 18px 48px rgb(0 0 0 / .18)`.
   - Фолбэк без `backdrop-filter`: плотная поверхность `--surface` с той же кромкой.
2. **Меш-градиенты с зерном.** Под стеклом мягкие пятна цвета (эспрессо, карамель, крема, кобальт), поверх шум через SVG `feTurbulence` в data URI, `mix-blend-mode: overlay`, opacity .25–.4. Весит почти ничего. На экране товара пятно цвета берётся из оттенка напитка (`--tint`).
3. **Шрифт как главный герой (кинетическая типографика, дозированно).** Крупные заголовки категорий и названия напитков. Вариативный вес «дышит» один раз при появлении экрана, цена прокручивается цифрами (`RollingNumber`). Бегущая строка допустима только в `HeroBanner`. Никакой постоянной анимации текста в списках.
4. **Бенто со смыслом.** Меню и профиль раскладываются плитками разного размера: размер = важность (хит продаж и «ваш обычный заказ» крупнее, остальные меньше). Одинаковые плитки подряд запрещены.
5. **Природные оттенки + один яркий акцент.** Нейтрали тёплые кофейные, акцент один, холодный и яркий (электрический кобальт), чтобы на фоне кофейных тонов он «звенел». Неон только как микро-акцент: активное состояние, статус заказа «готов».

**Исключено полностью:** тактильный брутализм (толстые чёрные рамки, жёсткие тени без размытия со смещением, «сырые» плакатные блоки). Также не использовать: фиолетово-синий градиент на весь экран, мягкие размытые тени на каждой карточке, одинаковый `rounded-lg` везде, эмодзи как иконки разделов, всё по центру, Inter/Space Grotesk.

**Типографика (всё с кириллицей, Google Fonts, подключить в `index.html` вместо Manrope):**
- Дисплей: **Unbounded** (variable 200–900): названия напитков, заголовки экранов, цены крупным кеглем, номер заказа.
- Текст и интерфейс: **Onest** (400/500/600).
- Редкий акцент (подзаголовки баннера, цитаты, «ваш обычный»): **Cormorant Garamond Italic**, не больше одного места на экран.
- Цифры везде `font-variant-numeric: tabular-nums`.
- Шкала: 12 / 14 / 16 / 20 / 28 / 40 / 56. Заголовкам `text-wrap: balance`, капс-лейблам letter-spacing .06–.08em.

**Форма и движение:**
- Радиусы по роли: стеклянные плавающие слои 28–32px, карточки 20px, чипы и капсулы 999px, поля 16px. Не всё одинаковое.
- Пружинные кривые: `--spring: cubic-bezier(.34,1.56,.64,1)` для нажатий и появления, `--ease-soft` оставить для переходов экранов.
- Нажатие любого контрола: `scale(.96)` + вспышка блика на стекле, 120–180 мс.
- `prefers-reduced-motion`: убрать перемещения и «дыхание» шрифта, оставить только fade.

## 4. Компоненты: как они должны выглядеть и работать теперь

Свобода полная, ниже — ожидаемое направление. Каждое решение должно быть удобнее или красивее текущего, а не просто другим.

### Модалки и слои
- **`Sheet`** → на мобильном настоящая bottom sheet из жидкого стекла с ручкой-хваталкой и **детентами** (половина экрана / весь экран), закрывается свайпом вниз с инерцией и резиновым сопротивлением. Фон под ней слегка уменьшается (`scale(.94)`, скругляется) и затемняется, как в iOS. На `wide` и десктопе — плавающая стеклянная панель, которая вырастает из элемента, по которому нажали (morph от точки нажатия), а не просто центрированная карточка. Escape, клик по подложке, `locked` и `aria-modal` сохранить. Фокус ловится внутри, при закрытии возвращается на кнопку-источник.
- **`ConfirmBox`** → не отдельная модалка-диалог, а компактный стеклянный поповер рядом с действием или «удержи, чтобы подтвердить» (кнопка заливается за ~600 мс, с вибрацией `navigator.vibrate` где доступна). Для разрушительных действий обязательно с возможностью отмены.
- **`Toast`** → капсула в стиле Dynamic Island сверху экрана (с учётом `safe-area-inset-top`): появляется из точки, растягивается до текста, может содержать действие «Отменить» (например, после удаления позиции из корзины). Стек максимум из 2.
- **`ShopPickerSheet`** → список кофеен как крупные карточки с расстоянием, статусом «открыто до 22:00» цветной точкой и временем ожидания; выбранная подсвечивается кобальтовой кромкой стекла.
- **`EmptyState`** → крупная типографика + иллюстрация кролика/чашки, один понятный призыв к действию.

### Навигация
- **`MenuDock`** → плавающая стеклянная капсула внизу, отделена от краёв, с «жидким» индикатором активной вкладки, который перетекает между пунктами. Счётчик корзины — маленькая капля, которая «булькает» при добавлении. При скролле вниз док сжимается до компактного вида, при скролле вверх раскрывается.
- **`CategoryNav`** → горизонтальные чипы, стеклянный индикатор перетекает под активной категорией и синхронизирован со скроллом меню (scroll-spy). Активная категория набрана Unbounded.
- **`MenuHeader`** → прозрачный в начале, превращается в стеклянную полосу при скролле; адрес выбранной кофейни как кнопка-капсула.
- **Переходы экранов** (`AnimatedOutlet`, `morph.ts`) → сохранить перелёт картинки напитка в чашку, усилить: фон экрана товара перетекает в меш-градиент цвета напитка.

### Меню
- **`HeroBanner`** → меш-градиент с зерном, крупный Unbounded, одна строка Cormorant Italic, допустима медленная бегущая строка с акцией.
- **`ProductCard`** → бенто: хиты и «ваш обычный заказ» занимают 2 ячейки. На карточке: арт напитка на мягком пятне своего оттенка, название, цена, быстрая кнопка «+» в стеклянном круге (добавляет размер по умолчанию с анимацией полёта в док).

### Товар
- **`SizePicker`** → сегментный контрол из жидкого стекла: «капля»-ползунок перетекает между S/M/L, чашка на экране плавно меняет размер, объём в мл и цена прокручиваются цифрами.
- **`AddonPanel` / `AddonTile` / `AddonChips`** → плитки добавок с тинтом (сироп карамель — карамельная плитка). Выбранная плитка: кобальтовая кромка + блик + лёгкое приподнимание; количество — встроенный степпер прямо на плитке, а не отдельные кнопки снаружи.
- **`NutritionBar`** → тонкие сегментные шкалы с подписями, без тяжёлых карточек.
- **`AddToCartButton`** → крупная плавающая стеклянная кнопка с кобальтовой заливкой, цена внутри прокручивается при изменении опций; по нажатию — короткая пружина, галочка и полёт мини-арта в док.

### Корзина и оплата
- **`CartLineItem`** → свайп влево для удаления с тостом «Отменить», степпер количества в капсуле.
- **`PromoField`** → поле-капсула; при успешном коде — анимация «купон приклеился», скидка прокручивается в итоге; ошибка с понятным текстом, как исправить.
- **`PickupPicker`** → горизонтальная лента времени («Как можно скорее», «через 15 мин», …) с перетекающим индикатором.
- **`PaymentPicker`** → способы оплаты как стеклянные карточки-«карты» в стопке, выбранная выезжает вперёд.
- **`LoyaltyOffer`, `UpsellRow`** → компактные бенто-плитки, не перебивают главную кнопку оплаты.
- Итог (`Summary`) → крупная цена Unbounded, строки скидок мелко и спокойно.

### Заказ, профиль, вход
- **`OrderStatusCard`** → живой статус: прогресс-трек с этапами, при статусе «готов» — мягкое неоновое свечение зелёного и вибрация. Номер заказа огромным Unbounded. `QrCodeView` на светлой плашке в любой теме (для сканирования).
- **`StampCard`** → физическая карта лояльности: 6–10 «оттисков» кофейного зерна, новый штамп ставится с анимацией печати; карта слегка наклоняется за пальцем/курсором (parallax, отключается при reduced motion).
- **`LevelCard`** → стеклянная карта уровня с меш-градиентом, прогресс до следующего уровня.
- **Вход** (`PhoneStep`, `CodeStep`, `NameStep`) → один вопрос на экран, крупный ввод; код из SMS — отдельные ячейки с автопереходом, вставкой из буфера и `autocomplete="one-time-code"`; ошибка — мягкое покачивание + текст.

## 5. Жёсткие ограничения

1. **Тесты.** Правило проекта: всё покрыто тестами. Перед началом прогнать `cd app && npm test` и зафиксировать исходное число тестов. После редизайна — **100% Passed**. Тесты ищут элементы по ролям, `aria-label` и текстам: сохранить доступные имена или осознанно обновить тесты вместе с компонентом. Каждый новый интерактивный паттерн (свайп-удаление, удержание для подтверждения, детенты шторки, отмена в тосте) — покрыть новыми тестами в RTL.
2. **Сборка.** `npm run build` (включая `tsc -b`) и `npm run lint` — 0 ошибок.
3. **Логика не меняется.** Домен (`src/domain`), API, запросы TanStack, роутинг и данные не трогать, кроме случаев, когда этого требует новое поведение UI (и тогда с тестами).
4. **Доступность.** Видимый фокус на всех контролах, клавиатурное управление шторкой и всеми новыми жестами (каждый свайп имеет кнопочную альтернативу), `aria-live` для тостов и статуса заказа, контраст AA, `prefers-reduced-motion`.
5. **Производительность.** Не больше 2–3 одновременно видимых слоёв с `backdrop-filter`; шум — data URI, без картинок; анимации только `transform`/`opacity`; 60 fps на средних Android. Никаких новых тяжёлых зависимостей без необходимости (анимации на CSS и Web Animations API; если нужна физика жестов — обосновать).
6. **PWA и устройства.** `safe-area-inset-*` везде, где слой у края экрана; раскладушки и планшеты (`wide`), десктоп — модалки как плавающие панели.
7. **Обе темы.** Каждый экран проверить в light и dark; ни одного цвета-литерала, работающего только в одной теме.

## 6. Порядок работы

1. Изучить `src/index.css`, `src/components/ui.ts`, все компоненты из раздела 1 и папку `screenshots/` (текущий вид). Прогнать тесты, записать исходный результат.
2. Новые токены, шрифты, утилиты (`glass`, `grain`, `mesh`, пружинные анимации) в `src/index.css` + обновить `ui.ts`.
3. Слои: `Sheet` → `Toast` → `ConfirmBox` → `MenuDock`. Это фундамент, остальное строится на них.
4. Экраны по порядку пользовательского пути: меню → товар → корзина → заказ → профиль → вход.
5. После каждого экрана: тесты, проверка в браузере (`npm run dev`) на ширинах 375, 768 и 1280, обе темы, reduced motion. Скриншоты «после» сохранить в `screenshots-after/`.
6. Финал: полный прогон `npm test && npm run build && npm run lint`, короткий отчёт: что поменялось в каждом компоненте, какие новые паттерны взаимодействия, какие тесты добавлены, что осталось нерешённым.

Критерий готовности: приложение узнаётся с одного взгляда как единая система «Espresso Glass», каждый экран выглядит как работа сильной дизайн-студии 2026 года, при этом заказ кофе стал быстрее или хотя бы не медленнее, а все тесты зелёные.
